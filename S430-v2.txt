## ⚠️ Edge cases handled
- Non-string queries -> tests call /search?query= with empty query; endpoints validate input type and return 400 for non-strings (Project A & B).
- Empty queries -> return empty results
- Ambiguous multi-term queries -> Project B uses overlapping tokens + fuzzy matching to boost relevant product score.
- Large datasets: current code is in-memory and small; for production scale, replace with an indexed backend (Elasticsearch, Whoosh, or SQLite FTS).

- Scoring is a heuristic; consider BM25/TF-IDF/learning-to-rank for better production results.
- Suggestions are simplistic (prefix match); could be improved with autocomplete trie or k-NN embeddings.
