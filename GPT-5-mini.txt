## Implementation notes, optimizations & edge cases handled
- Project A (pre-feature):
  - Very simple substring matching (lowercased). Returns a binary match with score 1.0.
  - Edge cases: non-string query raises TypeError; empty/whitespace returns empty list.
- Project B (post-feature):
  - Scoring uses RapidFuzz's `fuzz.ratio` (fuzzy similarity) and token overlap to compute a float relevance score.
  - Suggestion system builds a small vocabulary from names/descriptions for prefix-based suggestions.
  - Recommendation uses tag overlap for related-product recommendations.
  - Edge cases:
    - Non-string query raises TypeError.
    - Empty query returns empty result list.
    - Recommendations return empty list if item id not found.
  - Performance: scoring uses a linear scan (OK for small datasets). With larger datasets, you should index tokens, use approximate nearest neighbors, or precompute embeddings for faster lookups.

## Limitations & next improvements
- Tests are currently “probe-based” and check presence of keys. They should be expanded to:
  - Compare returned item IDs and scores against `test_data.json` expectations explicitly for each test case.
  - Compute end-to-end accuracy metrics (precision/recall at K), and latency histograms for many queries.
- Recommendation algorithm is simplistic (tag overlap). A better approach:
  - Learn item embeddings and compute nearest neighbors.
  - Use collaborative filtering from user behavior.
- For large datasets, use inverted indexes and optimized fuzzy search libraries or vector search engines (e.g., Faiss, Milvus).
- The current run scripts start servers via `cmd /C ...` to background them. For robust CI, use process supervisors or run tests that start/stop servers within the test harness.
